## 2. 核心公式：两次映射

不能直接把“女孩”替换成“AI”。正确链路是：

```text
关系事故
→ 抽象机制
→ AI 使用现象
```

例如：

```text
代理人只拿到部分聊天记录，按最近线索猜错约会地点
→ 信息缺失时，根据局部高概率线索补全空白
→ AI 生成听起来合理、事实却不存在的答案
```

高质量映射必须同时对上五层：

| 映射层 | 关系故事 | AI 现象 |
|---|---|---|
| 角色 | 你、对象、代理人、竞争者 | 用户、模型、Agent、工具或审核者 |
| 目标 | 追到、维持、升级、避免失去 | 完成任务、提高质量、保持稳定 |
| 信息 | 隐瞒、缺失、互通、逐步暴露 | 上下文、训练模式、检索结果、观测信号 |
| 动作 | 评论、回复、冷淡、试探、拒绝 | 生成、调用、继承、校准、停止 |
| 结果 | 上头、翻车、失去、停滞 | 幻觉、误判、污染、浪费、任务失败 |

最低验收标准：去掉概念名，关系事故仍能演明白因果；去掉两性词汇，故事仍能逐项换回 AI 变量。

## 3. 关系几何与主体结构

### 3.1 关系几何库

先选关系结构，再写人名和细节。

| 关系几何 | 核心机制 | 适合迁移的 AI 现象 |
|---|---|---|
| 多人隐藏互联 | 局部错误沿连接扩散 | 共享上下文污染、多 Agent 串错 |
| 稳态被外力击穿 | 过去稳定无法覆盖罕见冲击 | 边界输入、接口或权限突变 |
| 信息不足、主动脑补 | 低信息输入诱发投射 | 模糊回答带来的“很懂我”错觉 |
| 高价值但不可见 | 价值存在不等于价值被感知 | 正确答案因结构差而不被采用 |
| 突然升级与长期积累冲突 | 工具升级不等于能力形成 | 换模型不能替代审美与判断 |
| 从履历反推需求 | 从线索提出需求假设 | AI 理解真实目标而非字面命令 |
| 被单一标签困住 | 表面信号遮蔽真实主体 | 流畅语气、排版掩盖事实错误 |
| 奖励忽冷忽热 | 变动奖励与开放回路叠加 | 反复重新生成、持续消耗 token |
| 行为逐步更新判断 | 新证据改变原有概率 | 动态更新对 AI 答案的信任 |
| 关系升级后状态突变 | 异常出现后需要诊断 | 长对话质量衰减、目标漂移 |
| 互动频繁但拒绝承诺 | 正反馈不等于完成 | AI 回复很多却不交付 |
| 代理人只有部分记录 | 局部线索驱动错误补全 | AI 幻觉、错误交接、检索遗漏 |
| 先出现的信息控制后续解释 | 首个数字或结论被赋予过高权重 | Anchoring Bias、先验偏差、错误估算 |

### 3.2 三类主体结构

| 主体结构 | 适用案例 | 推荐长度 | 核心骨架 |
|---|---|---:|---|
| 事故揭晓型 | 1-3、代聊失真型 | 短版 150-190 字；扩展版 200-240 字 | 关系设定 → 异常 → 升级 → 结果 → 现象命名 → 机制 |
| 观点映射型 | 4-8 | 200-260 字 | 常见误区 → 反常识判断 → 变量重命名 → 反例或处方 → 收口 |
| 决策模型型 | 9-11 | 240-320 字 | 高焦虑症状 → 专业模型 → 信号或分支 → 决策规则 → 停止线 |

#### 事故揭晓型

```text
你进入一段有明确目标和风险的关系
一个小异常出现，并通过连续动作造成更大结果
对方或你付出可见代价
这就是【AI 使用现象】
它指的是【起因】通过【路径】导致【结果】
```

#### 观点映射型

```text
如果你以为【常见做法】会自动带来【结果】，那就错了
真正决定结果的不是【表层变量】，而是【底层变量】
【关系反例或行为处方】
在 AI 使用中，【关系变量】对应【AI 变量】
```

#### 决策模型型

```text
你遇到一个常见但让人焦虑的关系症状
不要先问【情绪问题】，先看【可观察信号】
如果出现 A、B、C，先做【低成本测试】
反馈为 X 就继续，反馈为 Y 就校准，仍无变化就停止投入
```

#### 事故揭晓型的派生：代聊失真型

```text
你因为【现实原因】，让【代理人】替你维持关系
但因为【具体事故】，他只拿到部分历史信息
对方问到一个记录中不存在的事实
代理人根据最近的局部线索，补出自然、具体但错误的答案
对方出现明确的负面反应
这就是【AI 使用现象】
它不是【错误拟人解释】，而是【信息限制 + 生成机制 + 缺少验证】造成的结果
```

四个问题缺一不可：为什么委托、为什么缺信息、根据什么猜、猜错造成什么后果。

### 3.3 高张力关系事故链

性张力不是身体描写越多越好。原文更稳定的做法是制造“关系马上可以升级，却被错误上下文瞬间毁掉”的落差：

```text
高价值对象与当前关系
→ 对方主动释放亲密信号
→ 关系马上可以升级
→ 旧的、错误的或冲突的信息介入
→ 主角按照错误上下文行动
→ 对方撤回亲密机会，关系立即受损
→ 这就是【AI 使用现象】
→ 用一句话解释信息如何影响后续判断
```

| 链路节点 | 写作作用 | 不能只写成 |
|---|---|---|
| 高价值对象 | 用顶美、稀缺选择权或强吸引力建立收益 | 随便一个无关人物 |
| 亲密信号 | 让观众看见关系即将升级 | 单纯介绍长相 |
| 错误信息介入 | 提供与 AI 机制同构的干扰源 | 为反转强塞误会 |
| 错误行动 | 把污染变成可视化行为 | 只说“你搞砸了” |
| 机会撤回 | 让错误立即产生关系代价 | 没有反馈就直接讲概念 |

性张力的核心是：**已经快得到了，却因为一次错误判断瞬间失去。**

同一个 AI 现象不要只想一个故事。先拆出 3-4 种不同的机制，再分别寻找关系事故。以上下文污染为例：

| 污染机制 | 关系映射 |
|---|---|
| 过期规则残留 | 把前任的相处规则继续用在新关系里 |
| 外部信息混入 | 把第三方的偏好误认为当前对象的偏好 |
| 新旧要求冲突 | 同时执行对方前后两条矛盾要求 |
| 上一任务残留 | 把上一段关系分析里的策略带进新的亲密邀请 |

### 3.4 原文比例与口播节奏

事故揭晓型优先使用短版：

- 总字数控制在 `150-190` 字；
- 关系事故占 `63%-76%`，概念命名和专业解释占 `24%-37%`；
- “这就是 X”放在全文约三分之二处；
- 全文保持 `3-5` 个主要句段，用逗号和转折词连续推进；
- 不把每个动作拆成电影化短句；
- 概念落点后只留一句硬解释，不继续展开讲课。

只有当机制必须交代额外验证过程时，才使用 `200-240` 字扩展版。

## 4. 七步写作流程

### 第一步：核验机制并拆成多个变体

先写 AI 现象的最短因果链：`什么先发生 → 通过什么路径 → 导致什么后果`。

再拆出 3-4 个互不重复的机制变体，例如过期残留、外部混入、新旧冲突、跨任务残留。不要围绕同一个故事只换人名。

关系人物可以有心理动机，但专业解释不能把“怕冷场、想撒谎、不愿认错”等人类心理直接安到模型身上。

### 第二步：提取六个变量

列出：主体、目标、已知信息、缺失信息、可见动作、最终损失。

### 第三步：为每个机制选择关系几何

从关系几何库选择因果结构最接近的一类。不要先想“小美、顶美、谁在追谁”。

### 第四步：搭建高张力事故链

先确定：高价值对象释放了什么亲密信号、关系原本将如何升级、错误信息怎样介入、主角做出什么错误反应、对方最终撤回什么机会。

性张力必须来自利益临界点和失去风险，不能只靠增加身体部位、暧昧词或床上场景。

### 第五步：补齐关系因果

事故必须回答：

1. 人物为什么采取这个行动？
2. 限制、误判或信息缺失为什么出现？
3. 哪个具体线索推动了错误判断？
4. 错误造成了什么可见后果？

### 第六步：区分细节并校准口播比例

- 结构细节承担因果：忙、手机坏了、记录缺失、最近聊日料、真实地点。
- 风格细节承担口吻：小美、顶美、夯爆、英文人名。

先补齐结构细节，再添加一到两个风格细节。删除某个细节后因果变弱，它才值得保留。

短版完成后复算：总字数是否为 150-190 字，关系事故是否占 63%-76%，全文是否仍是连续口述而不是电影化分镜。

### 第七步：落现象并校正机制

- 概念揭晓前，关系故事必须独立成立；
- 专业解释只保留起因、生成路径和后果；
- 事故揭晓型让现象名优先出现在全文 63%-76% 位置；
- 观点型和决策型可以更早给判断，但不能先讲长定义；
- 优先级：机制准确 > 关系因果完整 > 后果可见 > 作者口吻 > 字数。
