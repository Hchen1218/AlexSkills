# 表达校准与使用示例

## 先读原稿，再写新故事

配合 originals.md 与 templates.md 使用。本页是编辑判断，不替代全文原稿。

原稿常用“人物关系已经成立 → 具体信息或规则进入 → 你采取行动 → 关系结果发生 → 这就是概念 → 条件、机制、结果”。例如锚定原稿不是只有“闺蜜说她好追”，而是前任一次约会亲上的信息影响你对贴耳说话的判断，导致你转头亲上去、被推开。动作和后果让偏差可见。

开头可以“你……”也可以“Grace 是……，你……”。英文人名、小美／顶美是口吻细节，关键是连续陈述。两性张力来自竞争、靠近、试探、暧昧升级或机会撤回，不需要每句都刻意刺激。

## 后半段怎样教会观众

先从原稿识别解释骨架，再把核验过的机制填进去：

> 这就是 [英文名／中文名]。当 [成立条件] 时，[专业主体] 会／可能 [作用过程]，导致 [专业结果]。

此处是创作填空模板，不是专业定义本身。需要静态定义时可先解释“衡量什么”，再讲变量如何联动；不为凑事故歪曲中性概念。解释篇幅不足时压缩故事重复铺垫，不能靠核对卡补救正文空洞。

历史 Harness 原稿的解释列出上下文注入、工具调用、权限边界、结果校验，分别承接前面的进度表、代聊、不能承诺、先确认。学的是这种对应，别把英文术语和故事各写一段却没有联系。

## 本次制作中已经明确的纠偏

- 金融概念不要用情侣借款、还钱等金融行为作主体；将专业变量真正转成关系选择、承诺、信息与行动。
- 更暧昧不等于增加几句撩人台词。强度要作用于故事决策，并由机制推到可见结果。
- 不把人物反复表达观点当作完整事故；要有因此采取的行动和后果。
- 默认连续陈述，少用一问一答的戏剧台词。
- 后半段解释条件、作用与结果，默认不转成泛泛的使用建议。
- 字数以原稿实际中文字符数比较，不把“20s”标题视为实测朗读时长。

这些来自制作反馈，不是已发表原稿，也不等于下面的新生成稿已经获用户认可。不要把会话试稿混进历史原稿库。
