# Eval 3 · mobile · with skill

> 离线行为回放：以下回应只检查教学行为与同步规则，不代表真实学习效果，也不声称能够访问用户电脑或已经导入数据。

## 助手第1轮

可以在手机同一个聊天里连续练两次，第二次中断也应保留已经完成的部分；其他没做的题不算失败。手机端不需要运行 Python，也不会直接访问你的电脑。

开始前需要从电脑端导出的这几样内容：独立教学说明、学习者摘要、进度包（含到期队列和活跃卡），以及机器生成的记录模板。还要保留包 ID 和学习者 ID。练习中每个阶段都要有明确带时区的时间；中断时把该阶段标为部分完成。

同一聊天可以继续使用这些材料。回电脑时，把两次练习产生的全部未同步记录一起交给电脑端校验和导入；手机端不自行重算 FSRS。若换一个新聊天，则要同时带上原进度包和全部未同步记录。

现在的一个准备任务：请确认你是否已经带了进度包和随包导出的机器记录模板。缺少模板时，我只能先做可读暂存，不能自创可导入的数据结构。

## 助手第3轮

同步时不要让排列顺序或重复内容改变历史：

1. 记录在文件里前后颠倒没有关系。电脑端会先校验，再按实际发生时间和事件 ID 确定性重放；第一阶段仍应发生在第二阶段之前。
2. 第一次记录若以相同 ID、相同规范化内容重复出现，只去重一次，不新增事件。
3. 同一个 ID 一份写“失败”、另一份改成“成功”，属于同 ID 异内容冲突。整个批次都应拒绝，不能静默选择成功，也不能因此丢掉原始失败。
4. 如果“成功”其实是后来又做了一次，它应是新的回忆事件，使用新 ID 和真实发生时间。如果原失败记录本身确实记错，则保留原事件，再按机器模板追加一个新的 `correction` 事件，用新 ID 指向被更正事件；历史仍保留审计痕迹。

正确做法是先恢复那条原始失败记录的原内容，移除同 ID 被篡改的版本；拿到机器模板后，再判断“成功”究竟是新尝试还是对旧记录的更正。由于当前没有模板，我不会替你杜撰可导入字段或 ID。

## 助手第4轮

不能用旧包覆盖电脑。旧包里的复习日期过时是正常的：手机只能暂按旧队列和近期失败项练；回电脑后应把有效记录导入现有历史，让电脑按真实时序重新计算，再导出一个新包。旧包可以留作档案，但不能覆盖更新后的历史。

“昨天早上”缺少确切日期和时区，不能随便补。协议要求明确的带时区 ISO 8601 时间；在信息补清前，该记录应保持待补，包含它的导入批次会整体拒绝，而不是猜一个时间后写入。请回到能确认日期、当地时区或设备记录的来源核对；核对不了就如实保留未知，不制造精确时间。

另外，前一轮已经明确提供的 `2026-09-17T09:00:00+08:00` 与现在“记不清时区”的说法彼此冲突，也需要先由你根据原始记录确认。电脑端不应替你选择其中一个。
